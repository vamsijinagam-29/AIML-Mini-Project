# CarWise AI implementation plan

## Scope and architecture

CarWise AI is a single-process web application. A Python FastAPI service owns the trained scikit-learn pipeline, dataset-derived metadata, validation, and inference. The same FastAPI process serves the compiled React/TypeScript frontend from `frontend/dist`, so Preview and deployment exercise the same origin and the UI never falls back to mock predictions. The uploaded CSV is copied unchanged into `data/original.csv`; `train.py` creates `data/cleaned.csv`, `artifacts/model.joblib`, `artifacts/metrics.json`, and `artifacts/metadata.json`.

The model uses only the eight columns present in the source file. `name` is treated as the vehicle model label, `year` and `km_driven` are numeric, and `fuel`, `seller_type`, `transmission`, and `owner` are categorical. Exact duplicate rows are removed only after measurement and documented. Invalid or missing values are dropped because the assignment requires valid, complete records for a reproducible baseline and the source dataset is expected to be complete.

The training script splits the cleaned data before fitting preprocessing. It compares DummyRegressor, Ridge Regression, Random Forest Regressor, and Gradient Boosting Regressor. Each candidate is evaluated on the held-out test set with MAE, RMSE, and R²; the selected model is the lowest-MAE model, with R² and RMSE reported alongside it. A compact cross-validation score is saved for the selected model. The full selected pipeline is refit on the training split only for the artifact used by the API; API prediction therefore uses the exact preprocessing pipeline fitted during training.

## Project structure

- `backend/main.py`: FastAPI app, request/response schemas, health, metadata, and prediction routes; serves frontend static files.
- `backend/model_utils.py`: artifact loading and validation helpers.
- `train.py`: deterministic dataset cleaning, model comparison, metrics, metadata and artifact generation.
- `data/original.csv`: byte-for-byte source dataset supplied by the user.
- `data/cleaned.csv`: reproducible cleaned dataset generated by training.
- `artifacts/`: serialized pipeline and JSON evidence consumed by the backend and displayed in the UI.
- `frontend/src/`: React UI and dashboard styling.
- `tests/`: pytest coverage for preprocessing, model loading, API validation, and prediction consistency.
- `README.md`, `REPORT.md`, `architecture.mmd`: student-friendly setup, evidence and explanation.

## Design direction

Three candidate directions were considered: “Track-day telemetry” (0.07), “Executive garage” (0.05), and “Night-market neon” (0.08). The chosen direction is **Track-day telemetry**.

- **Design Movement:** premium automotive instrumentation inspired by a dark cockpit, with orange signal lights and crisp data panels.
- **Core Principles:** decision-first hierarchy, evidence over decoration, tactile controls, and calm high-contrast readability.
- **Color Philosophy:** charcoal and ink backgrounds keep focus on the forecast; warm orange marks the active decision and communicates motion; muted blue-gray supports technical evidence without competing with the price.
- **Layout Paradigm:** a left-rail command center with a large forecast stage, then evidence panels that widen into a data story instead of a centered card grid.
- **Signature Elements:** thin telemetry rules, a vertical orange “signal” bar, and price readouts with tabular numerals.
- **Interaction Philosophy:** every control explains its data constraint; submit is explicit and optimistic, while validation is immediate and specific.
- **Animation:** subtle rise/fade on panels, a slow shimmer only during prediction, and no perpetual motion that distracts from form completion.
- **Typography System:** Inter for UI and headings; IBM Plex Mono for metrics, labels and dataset facts.
- **Brand Essence:** a transparent resale estimate for Indian used-car decisions, built from real data and a real model; precise, candid, useful.
- **Brand Voice:** headlines are direct (“Price the next move.”); microcopy is honest (“A model estimate, not a promise.”).
- **Wordmark & Logo:** a compact orange bracket/road-mark symbol paired with the CarWise AI wordmark.
- **Signature Brand Color:** signal orange `#F97316`.

## Build workflow

1. Install Python dependencies from `requirements.txt` and frontend dependencies from `frontend/package.json`.
2. Run `python train.py` against `data/original.csv`.
3. Run `npm --prefix frontend run build`.
4. Start `uvicorn backend.main:app --host 0.0.0.0 --port 3000`.
5. Run pytest and the frontend build, then verify `/health`, `/metadata`, `/predict`, and `/manus-routes.json` against the running service.

The deployment shape is a containerized FastAPI service with the frontend compiled during the image build. The app honors `PORT` at runtime and exposes `/health` as the unauthenticated readiness endpoint.
